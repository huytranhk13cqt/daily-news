### 🔭 Overview (Tổng)
Denodo announced general availability of Denodo Platform 9.5 on 16/07/2026 via GlobeNewswire, with coverage on BigDATAwire and AIThority following on 17/07/2026. The release repositions the data virtualization layer as an "active context" tier for agentic AI, analytics and self-service data delivery, with the CTO Alberto Pan framing the goal as giving AI systems a substrate that understands business context, trusted metrics, live operational data and governance in one place. This is the first Denodo cut where Metric Views, vector search and expanded Databricks/Iceberg connectivity all land in the same release rather than as staggered previews.

### 🔬 Details (Phân)
The headline addition on the semantic side is native Metric Views: semantic-layer objects for defining and governing business metrics and KPIs so they can be reused consistently across data products, BI tools and AI experiences without being re-derived in each downstream. This lines Denodo up with the same architectural direction Apache Spark 4.2 chose earlier this week when it introduced its own in-engine Metric Views — the industry is converging on the pattern that governed metrics belong in the query layer rather than in a bolt-on Cube.js or LookML tier. On the connectivity side, 9.5 adds a Databricks connector, ships an Azure AI Search integration, adds vector search with proper indexes for semantic and document queries, deepens Delta table support and improves efficiency of the Denodo Lakehouse Accelerator against Iceberg. Unstructured data handling has been improved to make it a first-class citizen inside the virtualization graph.

The Data Marketplace has been extended into what Denodo is calling a 360-degree enterprise knowledge graph, adding asset extensions so ETL processes, consuming applications, notebooks, business glossaries, data dictionaries, governance controls, data product contracts and AI skills all become nodes and relationships in the same graph as the tables themselves. The Denodo Assistant — the natural-language front end that generates VQL and helps users navigate metadata — receives improved reasoning and disambiguation, and an interactive workflow for metadata exploration and VQL generation, framing it as the interface layer that agents talk to rather than a chatbot bolt-on. The positioning is deliberate: for organizations that already run Denodo as their federation layer above a mix of Snowflake, Databricks, Iceberg lakes and operational databases, 9.5 is meant to be the release that carries them into the agentic-workload phase without rebuilding the data plane.

For teams evaluating adoption, the operational shape is straightforward: 9.5 is a minor version and Denodo customers on 9.x will upgrade in place, but the new Metric Views object type will need to be modelled from scratch and the Databricks and vector-search connectors require credentials, workspace endpoints and index provisioning. The Iceberg improvements arrive as configuration flags on the Lakehouse Accelerator rather than as a new deployment shape, so existing Iceberg-backed workloads should see the efficiency gains after a restart with tuning applied.

### 🎯 Takeaway (Hợp)
If Denodo is already the federation tier in your stack and any downstream team is drafting an AI-agent proof of concept, prototype a Metric View for one production KPI in a 9.5 sandbox this sprint and route the Denodo Assistant against it end-to-end so you can measure whether the "governed metric plus vector search plus VQL generation" story replaces a separate semantic-layer product. Nếu chưa dùng Denodo, dùng release note này như tín hiệu để đánh giá lại các stack semantic-layer riêng lẻ trước khi mở rộng.

## 2. Espressif Publishes esp-aliro SDK Bringing CSA's Aliro Digital-Key Standard to ESP32-C and ESP32-H Smart Locks

| Field | Value |

### 🔭 Overview (Tổng)
Espressif published an announcement on its developer blog on 16/07/2026 introducing esp-aliro, an SDK that implements the Connectivity Standards Alliance's Aliro digital-key standard on top of Espressif's WiFi and Thread SoCs, with CNX-Software covering the release on 17/07/2026. Aliro was ratified by the CSA earlier in 2026 as a vendor-agnostic protocol for mobile access credentials — the same "phone or wearable as a digital key" pattern that Apple Home Key and Google Digital Keys have shipped separately — and this SDK is the first widely-available Espressif silicon reference implementation. The intent is to let a smart-lock or access-reader vendor pair an Espressif SoC, an NFC frontend and a lock actuator, and get an interoperable Aliro device without needing a proprietary stack.

### 🔬 Details (Phân)
Technically, esp-aliro ships with initial support for Aliro over NFC, exposing the Standard Expedited Phase, Fast Expedited Phase and Reader Certificate Sending flows a compliant reader has to implement, and pairs cleanly with an ST25R3916-based NFC frontend that CNX-Software's example uses on an M5Stack development board. The SDK supports all Matter-enabled Espressif chipsets, including the ESP32, ESP32-C, ESP32-S and ESP32-H series — practical targets are ESP32-C6 for combined WiFi and Thread, and ESP32-H21 or ESP32-H4 for Thread-only lock designs. Aliro is deliberately co-designed with Matter: Matter provides commissioning, remote control and management over WiFi or Thread, while Aliro handles the local NFC tap-to-unlock transaction between the user's phone and the reader, with `SetAliroReaderConfig` and `ClearAliroReaderConfig` commands living inside the Matter Door Lock cluster.

The gap in the current release is transport: Bluetooth LE and BLE-plus-UWB support are on the roadmap but not scheduled to a specific version, which matters because the Apple Wallet and Google Wallet flows for the Aliro standard include BLE and UWB modes for hands-free unlock. Vendors shipping today can build a fully compliant tap-to-unlock reader, but a hands-free entry SKU will need to wait for a future SDK cut. Positioning-wise this is the same pattern Espressif has run with Matter itself — get the reference SDK out early on the standard so third-party lock vendors can converge on Espressif silicon before larger MCU vendors ship comparable stacks — and it lands into a market where DIY builds (like the community-published ilia.ae PN532 reader) have been demonstrating the underlying transactions but without a first-party SDK to lean on.

Operationally, the source and demo repositories are already on GitHub as espressif/esp-aliro, meaning firmware teams evaluating Aliro can pull the code today and start bringing up hardware against the NFC path, rather than waiting for a certification-track partner engagement. Everything ultimately still routes through CSA certification for shipping products, so treat the SDK as the development stack, not a fast path around the compliance program.

### 🎯 Takeaway (Hợp)
If you are shipping or planning a Matter-over-Thread smart lock in the next 6-12 months, clone `espressif/esp-aliro`, bring up the reader example on an ESP32-C6 or ESP32-H21 board paired with an ST25R3916 NFC frontend, and validate the NFC tap-to-unlock flow against an Aliro-compliant iOS or Android device before scoping the BLE/UWB path. Skip until later if the target product is Wi-Fi-only cloud-first and the local digital-key path is not on the roadmap.

### 💡 Example
```c
// Sketch of an ESP-IDF component picking up esp-aliro on an ESP32-C6 lock.
// The Matter Door Lock cluster owns Aliro reader configuration; esp-aliro
// handles the actual NFC transaction with the phone.
#include "esp_aliro.h"
#include "esp_matter.h"

void app_main(void) {
    esp_matter::endpoint::door_lock::config_t lock_cfg = {};
    esp_matter::endpoint_t *lock = esp_matter::endpoint::door_lock::create(
        node, &lock_cfg, ENDPOINT_FLAG_NONE, NULL);

    esp_aliro_config_t aliro_cfg = {
        .transport      = ESP_ALIRO_TRANSPORT_NFC,      // BLE / UWB planned for later
        .reader_group   = "front-door-readers",
        .cert_provider  = esp_aliro_cert_provider_default(),
    };
    esp_aliro_reader_init(lock, &aliro_cfg);
    esp_aliro_reader_start();
}
```

### 🔭 Overview (Tổng)
Seeed Studio's reCamera Pro was covered on CNX-Software on 17/07/2026, opening pre-orders on the 2 GB variant at $299.90 with shipping scheduled for 29/07/2026 and a 4 GB variant landing within three months. The device is positioned as an open AI camera — Seeed publishes hardware design and firmware sources — and its point of interest is that it consolidates the four workloads that would normally need a separate NPU box, an LLM appliance, an ASR engine and a TTS engine into one PoE-powered camera enclosure. That framing is what makes it more than a "camera with a slightly bigger NPU" launch: it is aimed at the emerging class of edge-AI camera deployments where the pipeline includes visual scene understanding, a chat interface and speech output.

### 🔬 Details (Phân)
The core silicon is Rockchip's RV1126B, a quad-core Arm Cortex-A53 SoC running at up to 1.2 GHz paired with a 3 TOPS INT8 NPU that also supports INT4, INT16 and FP16, with a documented compatibility list that includes TensorFlow, ONNX, PyTorch and Caffe model imports. Memory is 2 GB or 4 GB LPDDR4 depending on the SKU, storage is 16 GB eMMC plus a microSD slot, and the camera path is an 8 MP SC850SL sensor supporting 4K at 30 FPS through an M12 mount with a 123 degree field of view. Connectivity is unusually complete for the price bracket: gigabit Ethernet with PoE — meaning a single cable powers and networks the device — plus dual-band WiFi 5, Bluetooth 5.4 and a USB 3.0 Type-C port. Audio is dual microphones and a 1 W speaker.

The software story is the differentiator. Out of the box the device runs Qwen2 0.5B locally at 13.63 tokens per second for a small on-device LLM, InternVL3 1B as the vision-language model for scene understanding, Whisper Base for speech-to-text and MMS-TTS for text-to-speech, exposed through a web UI plus RTSP, ONVIF and MQTT protocols for integration into existing NVR and Home Assistant stacks. This is the same class of models that has been running on Jetson Orin Nano and Raspberry Pi 5 with a Hailo-8 shield for the past year — the reCamera Pro's claim is that it packages them at a lower unit cost, in a purpose-built enclosure with PoE, and with the firmware pre-integrated. The obvious competitors are the ESP32-P4-based AI camera line, the Frigate NVR plus Coral TPU setup, and various Rockchip RK3576 modules being sold as generic edge boxes; the reCamera Pro's differentiator is the LLM plus VLM plus STT plus TTS bundle running on one power budget.

Operational caveats worth flagging before designing around it: 13.63 tok/s for Qwen2 0.5B is real but modest — this is not a device that will host a general chat interface for a family — and the InternVL3 1B model is only usable for narrow VLM tasks (scene captions, targeted queries) rather than open-ended visual reasoning. The 4 GB SKU is unpriced and shipping is "within three months", so any product roadmap depending on the higher-memory variant should assume Q4 2026 for volume.

## 4. Olimex PICO-EVB Turns the Raspberry Pi Pico Family Into a Sub-€15 Industrial Automation Board With 240V AC Relays

### 🔭 Overview (Tổng)
Olimex's PICO-EVB automation carrier board was covered by CNX-Software on 17/07/2026. The board is a 100 by 70 mm carrier that turns any Raspberry Pi Pico, Pico 2, Pico W, Pico 2 W or Olimex RP2040-PICO30 into an industrial-grade automation controller with four optoisolated 240 V AC relays and four opto-isolated 30 V DC or 220 V AC inputs, sold at €14.95 without a Pico board. The interest is not the silicon — the RP2040 and RP2350 are already well-known — but that Olimex has packaged the mains-voltage front end that DIY builders typically hand-solder onto perfboard into a single audit-ready KiCad-published board at commodity price.

### 🔬 Details (Phân)
The relay bank is four opto-isolated units rated 15 V DC at 10 A or 240 V AC at 10 A, and the input bank is four channels accepting either 3.3 to 30 V DC or 110 to 220 V AC, all with eight status LEDs on the carrier so a technician can eyeball state without connecting to the Pico. Connectivity is a USB Type-C, a UEXT connector exposing I2C, UART and SPI, and an unpopulated 18-pin GPIO header for extension. The board is specified for an industrial temperature range of minus 45 to plus 85 degrees Celsius, which is the interesting spec because it makes the PICO-EVB usable in outdoor cabinets and unheated warehouses where most educational Pico carriers are not qualified.

Software support ships in a form that reflects how the board will actually get deployed: Arduino and MicroPython code samples for teams that want to write firmware directly, and ESPHome YAML for teams that will connect it into Home Assistant as an automation node. The important design choice is that Olimex has published the KiCad design files on GitHub, meaning any hardware team can fork the schematics — for example to add a fifth relay, swap the input opto-isolators for a specific certification target, or drop the whole front end into a larger custom board. Positioning-wise, this competes with the Sonoff and Shelly relay modules on the WiFi-first end and with more expensive Raspberry Pi HATs on the Pi-Compute-Module end; the PICO-EVB's angle is "the mains-voltage front end and the microcontroller are decoupled, so you can move to a Pico 2 W or an RP2350 board without touching the automation wiring".

Caveats to keep in mind: the relays are rated at 10 A but sustained mains-voltage switching still requires proper enclosure, fusing and local electrical code compliance, and none of that is included in the €14.95 price — this is a hobbyist and small-integrator board, not a UL-listed appliance. The unpopulated 18-pin extension header also means adding an SD card, external ADC or Ethernet daughterboard needs manual header soldering.

### 🎯 Takeaway (Hợp)
If you are prototyping a Home Assistant or ESPHome node that needs to switch mains loads — pumps, lights, HVAC actuators — order one PICO-EVB with a Pico 2 W and use it as the reference board for the wiring, then decide later whether to stay on the carrier or fork the KiCad files into a custom PCB. Not the right pick for a device that will ship in tens of thousands of units — at that volume, a bespoke board with certified mains-voltage components will be cheaper per unit and pass regulatory review more cleanly.
